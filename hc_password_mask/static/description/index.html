Password Mask

Passwords, API keys and tokens shown with password="True" never reach the browser — not even in DevTools.

Masked on the server Zero config Works on any model Community & Enterprise
The problem

The dots only hide what is drawn

In standard Odoo, password="True" only changes how the input is drawn. The real secret is still sent to the browser, so anybody sitting in front of an open form can:

✗  press F12, change the input to type="text" and read the API key in clear text, or
✗  open the Network tab and read it in the JSON response of web_read.
What the browser receives Standard Odoo With Password Mask

JSON response in the Network tab "api_key": "sk-live-9f2c…" "api_key": "********"
Exported spreadsheet real value ********
How it works

Masked before any data leaves Odoo

Masking happens on the server. A placeholder (********) is sent instead of the real value, and when the form is saved with the placeholder untouched, the stored value is kept as it is.

<!-- your existing view, nothing to change -->
<field name="api_key" password="True"/>

<!-- what the browser gets after installing the module -->
<input type="password" value="********">

Left untouched

Save the form and the real value stays in the database.

New value typed

Save the form and the new value is stored normally.

Field cleared

Save the form and the value is removed.
What you get

Every way a secret could reach the browser, covered

Automatic detection

Every char/text field displayed with password="True" in a form, list or kanban view is protected, including inherited views and one2many sub-lists.

Covers every UI channel

Form and list loading, onchange results, saving, and direct read / search_read calls made from the browser console.

Safe saving

The placeholder is never written back. Settings pages (res.config.settings) keep their stored keys when you click Save.

Your code keeps working

Python code, crons and integrations still read the real value: only data sent to the web client is masked.

Export and import guard

Password columns are masked in exports, and importing a file that still contains the placeholder is refused so secrets are never overwritten.

Hides the length too

The placeholder always has the same length, so the number of dots no longer reveals how long the secret is.

How to use it

Install the module — that's it. There is no configuration and no view to change: fields are discovered from your views and the list refreshes automatically when views are added or modified.

Good to know

This module protects the web interface. It complements, but does not replace, Odoo access rights.

Some users should not see a secret at all?
Still restrict them with groups="..." on the field.

Do XML-RPC / JSON-RPC integrations get the placeholder?
No. External integrations receive the real value, as they need it.

Is the chatter history masked?
No. If a field is tracked in the chatter (tracking=True), its chatter history is not masked.

Can a secret be literally ********?
No. A secret whose real value is exactly the placeholder cannot be saved.
